## Release policy and external ruleset

[Publication policy](../../../../deploy/release/publication-policy.json) preserves automated qualification/license deferrals only for v1.2.0 and v1.2.1. The historical automated validator consumes the policy and rejects later tags. Existing signed/released bytes and waiver contents were not rewritten. Future tags default to strict signed release approval, passed vulnerability/license qualification and no deferred qualifications. A maintenance automated alternative remains `not_approved` with no applicable tags. Its explicit approval decision is required only before publication; implementation continues independently.

Future runtime waivers require an exact tag and image digest, category and finding IDs, reason/approver, owner, verification evidence, expiry, and an upstream-availability check no older than seven days. Available compatible fixed upstream artifacts must be adopted. If no fixed artifact exists, or incompatibility has retained evidence, an exact expiring waiver may retain the findings without an Astronomer fork. Historical tag waiver dates were not renewed. No future release or expiry decision was approved here.

Recommended response policy is daily triage, fixes within three days for critical/exploited findings and seven days for HIGH findings where a compatible fix exists. No-fix or incompatibility cases need an owned, documented, exact expiring exception and retained findings. Release owners may explicitly choose a different documented SLA. Vulnerability, license, FIPS and accessibility evidence remain separate; a CVE waiver supplies none of the other qualifications.
