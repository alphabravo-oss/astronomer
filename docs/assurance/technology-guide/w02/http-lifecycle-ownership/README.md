# HTTP lifecycle ownership

The original agent health server created a context waiter even when binding failed and could return before its blocked shutdown owner finished. The two public agent fixtures demonstrate those exact failures; the strict before runner rejects setup, cleanup, timeout, and unrelated failures with the same test names. Both intended diagnostics occurred, with zero skips.

The shared HTTP helper now owns Serve and Shutdown together, uses a fresh bounded shutdown context, falls back to closing the server, and joins the shutdown owner before returning. The agent binds its listener before creating that owner. Worker metrics use the same helper while preserving their existing lifecycle behavior and responses. This does not claim to drain arbitrary context-ignoring handler goroutines. The held Prometheus collector in the test has its own explicit release and bounded cleanup join.

After the change, eight lifecycle parents across agent, worker, and the shared helper passed under the race detector with three package passes and zero failures or skips. The direct shared-helper fixtures exercise actual sockets, response behavior, listener closure, and Serve failure. Vet, the centralized environment-access test, cached JSON governance, dependency boundaries, and complexity passed. All seven process groups were held until drain; all 38 capacity guards passed, and source and selected Go 1.27.2 identities remained stable.

[packet.json](packet.json) indexes 21 lossless gzip artifacts and two complete Git source maps. Stored and decompressed identities bind the original private outputs, approved drivers and controls, shared finite process helper, and reviewed production patch. The original output directories remain available for independent verification. The earlier permissive before runner was revoked before launch; only the strict diagnostic runner produced the retained before result. This is scoped lifecycle qualification, not whole W02 or current repository-wide security acceptance.
