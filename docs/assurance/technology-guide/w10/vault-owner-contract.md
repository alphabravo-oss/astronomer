Vault metric lookup capture occurs before the connection database read. The verified row binds a connection-ID lease before client construction, secret fetch or health/test probe. Resolver dedupe retains the bound observer per connection for the duration of the call. Audit context still records the original display name and reference; missing/unverified names share the fixed `unknown` metric value.

The `connection` label key is retained, but its qualified value changes from display name to the verified UUID. Existing source consumers were the resolver observer and health/test handlers; they now bind verified leases. No maintained dashboard/alert query selected a Vault connection-name value at this source boundary. `docs/vault-integration.md` explicitly documents the value migration. The product's UpdateVaultConnection does not rename Name. ID labels prevent old display-name owners from sharing or deleting a new connection's counter children after delete/recreate.

The registry admits at most 10,000 owners across process instances. Overflow is metrics-only and exports a finite `budget_dropped` result. Current owner's counters are preserved across new captures and credential update/cache invalidation. Committed handler deletion removes the owner and all its three finite outcome counters, duration histogram and health gauge. Pointer identity prevents a captured late callback from recreating those children.

Before the database lookup, a token captures admission serial and publication epoch without allocating an owner. Committed deletion or any complete current-owner observation increments the epoch, fencing outstanding unbound lookups without storing deleted-ID history. A lookup whose epoch changed drops metrics (`late_dropped`); its product result and audit are unchanged. Already-bound callbacks remain valid for a live owner. Admission serial originates at lookup start, so an old lookup bound while a newer absent snapshot is in flight can still be retired, while a genuinely newer lookup is protected by the collection watermark.

The supervised collector runs one observation at a time every 15 seconds. Each observation uses a 10-second read-only repeatable-read transaction, at most 21 pages/10,000 owners, context checks independent of the driver, and a fresh two-second rollback context. It uses the existing credential-free canonical ListVaultConnectionsPage projection; only UUID/name membership is retained page by page. Error, iterator failure, canceled or failed-commit observations do not call retirement. Invalid/duplicate/over-budget observations cannot modify the current registry. The existing health method moved into `vault_health.go` to reduce the oversized CRUD unit; only its original file ceiling is lowered.

Source and tests are prepared for review; no runtime or database qualification is claimed at this boundary. The extra database collector's workload and real snapshot behavior remain unmeasured. Other metric owner families, full observability race, actual collector readback/workflow propagation and fleet/throughput overhead remain open.

The finite Vault observation counter distinguishes complete, owner_budget, invalid, canceled and failed results. Its last-complete timestamp records collection start and is updated only after successful complete retirement publication. Context is checked immediately after transaction commit, so a driver that ignores cancellation cannot expose expired rows. The source health contract bounds unrecognized diagnostics to failed; it does not publish arbitrary error strings.

For one stable process-instance label, the Vault upper bound is 18 ordinary metric series per admitted owner: three outcome counters, an eleven-finite-bucket histogram (12 bucket series including infinity plus sum/count), and one health gauge. Unknown/unbound observations contribute at most the same 18 constant series; finite admissions, observation results and completion time contribute nine. Registration contributes one phase gauge per owner, up to 78 global terminal-duration histogram series (three outcomes × two baseline values × 13 histogram series), and ten finite admission/observation/time series. These are structural upper bounds, not measured active series, memory cost, fleet capacity or an agreed overhead budget. The admitted owner ceiling can drop telemetry before exhausting product capacity, explicitly shown by budget_dropped counters.
