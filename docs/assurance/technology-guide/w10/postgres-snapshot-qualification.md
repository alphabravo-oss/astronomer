The PostgreSQL snapshot harness is a draft qualification lane until both maintained majors have actual receipts. Its three required parents call the unchanged production connection, registration-phase and credential-free Vault collectors. Each reads 501 rows across the 500-row page boundary while a second connection commits a deletion, insertion and name or phase changes between the pages. The first observation must retain exactly the original identities and values; a subsequent transaction must observe exactly the changed set. The test also reads PostgreSQL's actual read-only and repeatable-read transaction settings.

Run `scripts/metrics-postgres-qualification.py --major 17` or `--major 18` with the protected exclusive reference, owned kubeconfig and an external artifact directory. The default command verifies ownership without writes; `--run` executes the three tests. Before the test process starts, the runner re-reads the owned namespace and cluster UUIDs and owner, discovers the current ready primary and its controller, and binds the reference host/port to the unique primary NodePort service and a node in that cluster. The allocation-time primary is provenance, never the execution target. The maintained capacity guard must pass, and the source must be clean.

The Go fixture binds the protected reference's SHA to that fresh fence and verifies the actual database name, server major and exact migrated schema before any fixture write. Each parent creates and drops only a unique schema in its exclusively leased metrics database. Its tables clone the current public table definitions, and production sqlc queries resolve against those clones. Public application rows, roles and keys are untouched. This tests production query and PostgreSQL snapshot behavior over synthetic rows; it does not execute application mutations, qualify deployed failover or measure representative fleet overhead.

A two-minute inner Go deadline and a three-minute outer process-group deadline bound execution. The exact three-parent inventory rejects zero tests, missing, duplicate, skipped, unexpected or failed cases. Raw structured events, source fingerprints, fresh ownership metadata and capacity results remain in the caller's external artifact directory. PostgreSQL 17 and 18 results remain distinct; neither is inferred from an in-process fake or another major.
