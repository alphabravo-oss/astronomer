# Bounded legacy continuation contract

The failing catalog ceiling fixture is corrected by validating the requested offset before a query or slice. `pagination.LegacyOffset` accepts the existing 0..10,000 compatibility range, retains the existing absent/malformed/negative fallback to zero, and rejects oversized or repeated offsets. The actual handler returns HTTP400 with `error.code:offset_not_supported`; no page is queried or repeated. A legacy collection also rejects an unsupported `cursor` parameter with `cursor_not_supported`. Cursor-capable producers keep their own binding checks.

The guard applies at 88 direct HTTP offset or `pageWindow` boundaries in 62 files. The two existing cluster cursor producers retain their cursor handling. Separate Charlie, delivery, SCIM and Kubernetes opaque-continuation parsers are not replaced by an API-global middleware. The in-memory producers retain their upstream behavior; this slice does not claim they became SQL keyset queries or that materializing arbitrary upstream resources is bounded.

Four oversized files required extraction of existing list code/helpers into narrow neighboring modules. Their complete diffs preserve authorization, query predicates, response projection and audit behavior; no ceiling increased. The complexity generator lowers only those four actual file counts. Existing overflow tests now assert explicit rejection before SQL while retaining accepted boundary coverage at 10,000.
