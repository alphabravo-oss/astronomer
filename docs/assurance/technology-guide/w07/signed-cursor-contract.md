# Signed canonical cursor codec

The existing `pagination.Cursor` remains the position envelope. Its legacy timestamp/ID codec remains unchanged on the wire. The new critical-collection codec uses the injected existing JWT key ring to derive independent pagination HMAC-SHA256 keys under `astronomer/pagination/key/v1`, and authenticates a versioned token domain with `hmac.Equal`. The first configured key signs; retained keys verify. Removing an old key rejects its tokens. No environment read, global key or public scope hash supplies signing authority.

The signed envelope supports timestamp/ID and text/group/ID positions, with a bounded2KiB payload and4KiB token. The text bound follows the existing255-character database name contract, including full-width Unicode; it does not incorrectly cap names to255 bytes. Its issue time expires after two hours with one minute of forward clock tolerance. Every producer binds current actor, authorization scope, filters and ordering and reauthorizes through its current scoped SQL predicates. A signature is not a substitute for those predicates.

The actual codec fixtures cover retained/removed rotation keys, stale/future timestamps, wrong actor/project/filter/order bindings, payload tampering, truncation, overlong values, Unicode names and unavailable signing authority ([receipt](signed-cursor-tests.log)). Missing authority cannot emit an unsigned `next_cursor`. This codec receipt alone does not qualify database traversal, authorization middleware or query cost; those are separate producer/integration receipts.

New crypto inventory: `internal/pagination/signed_cursor.go` owns HMAC-SHA256 key derivation and token authentication. Existing configured signing material remains under the JWT authority and rotation procedure; there is no new operator secret or encryption role. W16's final native crypto inventory must include this source. Exact JSON governance records the new marshal and authenticated canonical decoder sites.
