# W03 network boundary evidence

This bounded slice implements canonical destination policy and the actual S3 connectivity probe. W03 remains in progress. No release, airgap, S3 write/read/list/delete/retention, RustFS, or CNPG qualification is claimed.

`internal/httpclient.DestinationPolicy` defaults to bounded public HTTPS. Private exceptions require an exact origin (scheme, canonical host, effective numeric port) and CIDRs. Restricted mode has no public fallback. Plain HTTP is permitted only for an explicitly configured private origin; it does not bypass the prohibited address classes. IPv4-mapped IPv6 is checked after unmapping. Trailing-dot/zone/ambiguous-port aliases, URL credentials, metadata, loopback, link-local, multicast, unspecified addresses, mixed DNS answers outside policy and response overflow are rejected. Strict distribution and S3 clients reject cross-origin redirects. Each connection independently resolves and connects directly to the validated IP. Ambient proxies are ignored; explicit proxies must satisfy policy.

The production delivery resolver now uses this canonical transport. Existing resolver source host/CIDR policy semantics remain explicit. Signed asset content cannot modify destination policy.

`BackupS3DestinationPolicy` and `BackupS3CAFile` are typed configuration injected by production composition. Stored storage endpoints cannot grant themselves private permission. The backup probe retains SigV4 authentication and path-style bucket listing, uses the canonical bounded client, and returns redacted errors without upstream response bodies. Existing authenticated API download paths have no functional browser presigning feature; no unused external endpoint configuration was added.

Optional environment bindings were extracted into a configuration helper to reduce the oversized `Load` function. The config generator reads both canonical files, and its fixture contract still rejects missing bindings. The complexity baseline ratchet removes only the reduced `Load` ceiling in this slice.

Validation: selected Go 1.27.2; `go test ./internal/httpclient ./internal/delivery/resolver ./internal/handler -run 'Destination|Network|ProbeS3|BackupS3' -count=1` passed. The transport tests exercise exact host/port/CIDR controls, mapped IPv4/IPv6, mixed DNS answers, check/connect rebinding, direct checked-IP dialing, cross-origin credential removal, and response bounds. S3 tests exercise existing probe behavior plus independent operator authority and upstream-error redaction. The S3 positive response is a unit transport fixture, not a RustFS qualification. `make config-docs-check` passed including three generator fixtures before this bounded commit; root reviews/reruns the isolated commit.

Further W03 work (separate commits): authenticated v2 closed BOM and signed child OCI production/export, actual provisioner injection, durable mirror transitions, disconnected catalog fetch paths, safe catalog import, inventory completeness, chart configuration, and runbook/status contracts.

Root review hardening: policy JSON `null` is rejected; plaintext CIDRs must be wholly contained in RFC 1918 or ULA (mixed ranges such as `10.0.0.0/7` are rejected). AWS `fd00:ec2::254` and Alibaba `100.100.100.200` metadata destinations are denied even inside approved origins/CIDRs. The copy test now exercises the constructed client after caller mutation and asserts rejection before its transport is called. Focused destination/resolver/S3 tests passed after these changes.

Legacy resolver compatibility: its explicitly selected public HTTPS redirect option permits public CDN targets, validates every target and every connection with public-only authority, and removes Authorization, Proxy-Authorization, Cookie, and configured secret headers. It cannot be enabled for restricted destination policies. A real TLS redirect fixture confirms successful checked-IP CDN delivery without credentials, rejection of a private redirect before dialing even when the original policy grants that private origin, and strict default rejection. `GOTOOLCHAIN=go1.27.2 GOMAXPROCS=4 GOFLAGS=-p=2 go test ./internal/httpclient ./internal/delivery/resolver -count=1` passed.

GCP `fd20:ce::254` is also explicitly denied, including inside an approved ULA CIDR. The address was verified against the [official Compute Engine metadata endpoint documentation](https://docs.cloud.google.com/compute/docs/metadata/querying-metadata). AWS, GCP, and Alibaba metadata exception tests exercise the actual constructed transport.

The docs complexity gate initially miscounted an opening-brace string literal as function nesting. Policy decoding now uses a typed pointer and rejects a nil decoded object, which directly enforces the object/null contract without prefix inspection. All HTTP client tests and the unchanged complexity gate pass. No baseline ceiling was added.
