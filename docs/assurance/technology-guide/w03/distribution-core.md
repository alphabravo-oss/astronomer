# W03 verified distribution implementation evidence

W03 remains in progress. This slice implements the signed parent/child contract, actual provisioner injection, immutable source projection, preparation producer, and emitted metadata consumer. It does not qualify vendor publication, a live disconnected cluster, supplier asset completeness, current Trivy database freshness, RustFS operations, or PostgreSQL 18/CNPG. Historical v1 preparation remains available and does not qualify the new v2 distribution contract.

The v2 OCI payload contains a closed BOM, exact original chart archives (including nested dependencies), coalesced reviewed values, immutable image inventory and render evidence. The BOM has explicit profile qualification, required categories, blocked categories, and typed members for CRDs, tools, operators, plugins, database assets, trust, vulnerability databases, runtime images and application catalogs. A qualified profile requires its core categories and every declared prerequisite. It rejects missing categories, mutable image references, missing architectures, ambiguous JSON, unsafe tar/gzip members and changed content. Operator overrides produce different reviewed catalog/profile bytes and require a newly authenticated distribution; they cannot mutate cached accepted inputs.

The production composition passes release-projected repository, parent subject digest, emitted catalog digest, exact publisher OIDC policy, operator-mounted offline trust and independent destination policy into the actual builtin provisioner. Explicit source-development uses embedded fixtures and is labeled unsigned-development. Production has no embedded fallback. Authentication precedes archive interpretation, and each chart child is separately authenticated with the same publisher policy before any provisioner mutation. Failures preserve previous accepted assets. Successful cache results and network/mirror policy inputs are copied to prevent caller mutation.

Each child is an immutable Helm OCI manifest whose layer is the unchanged reviewed supplier chart archive. The parent binds both child manifest digest and original archive SHA. The persisted Source is Helm OCI and uses that manifest digest; Flux materialization already uses digest-pinned OCIRepository/chartRef with signature policy. Original upstream location and archive SHA are retained as audit metadata. Parent authentication cannot authorize a mutable HTTP chart refetch or an unsigned child. Operator mirror endorsement adds exact source-manifest/distribution/catalog binding, without replacing publisher trust or changing content digests.

Distribution and mirror endorsement identity enter deterministic source/version identity. Target ownership remains stable. Serializable PostgreSQL transactions retain old public versions/sources, increment the target generation only for a new immutable version, and leave retry generations unchanged. Normal product rollout planning remains the reconciliation path.

The producer performs actual offline Helm rendering with full effective values, hooks and nested image fields, and classifies values for operator-generated downstream images. Unrenderable charts, mutable image/database inputs and undeclared images fail. Architecture preparation consumes digest-bound supplier indexes, child manifests and configuration bytes; configuration OS/architecture must agree with the index. External layer fallback URLs are rejected. Qualified output is deterministic, goes into a new local OCI layout, and is checked by the consumer's exact archive validator. Preparation performs no publication or signing. The narrow `--v2` build path preserves the historical v1 path. Release manifest generation accepts the emitted `subjects.json` only after the canonical Go layout validator binds parent, child, payload and catalog bytes; it uses the emitted coalesced catalog, including when the legacy catalog path is absent.

Validation used Go 1.27.2 with GOMAXPROCS=4 and GOFLAGS=-p=2. Full focused Go suites passed for distribution, producer, builtin, resolver, releasecontract, config and bundles; terminal events are retained in `distribution-core-tests.jsonl`. The ordinary suite skips the two opt-in PostgreSQL tests. The separately executed owned PostgreSQL 16 container fixture passed all 16 actual test/subtest terminal records, including automatic scanning, concurrent retries, conflict rollback, mirror transition and repeated distribution generation. Its private random credential/DSN were never retained. The initial fixture failure (key-based trust incorrectly included an OIDC identity) is retained separately; its correction and final results are source-visible. This fixture makes no PostgreSQL 18/CNPG claim.

The real HTTP registry QA test uses ephemeral ECDSA keys and the production OCI verifier/payload reader. It signs the parent and each child, verifies and projects them, then checks that missing child signature, changed child bytes and wrong mounted QA key cannot reach the accepted cache. The wrong-key assertion proves rejection before reading the parent archive. Unexpected public trust requests are denied. QA identity is `cosign_key` with mounted `qa.pub`; it is not Astronomer's GitHub OIDC publisher. This test does not prove the selected Cosign CLI producer interface or vendor artifact execution; that qualification remains separate.

Config docs and generator fixtures passed. Dependency boundaries passed. The unchanged complexity gate then passed. No budget ceiling was added.
