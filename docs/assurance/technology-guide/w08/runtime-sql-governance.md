# W08 runtime SQL and deletion ownership

The four selected services moved sixty unique fixed statements into canonical sqlc sources, in independently reviewed slices: systemrelease (5), catalogapp (17), builtin (15), systemrollout (23). Transaction/session placement and behavioral receipts are in [systemrelease](systemrelease-sqlc.md), [catalogapp](catalogapp-sqlc.md), [builtin](builtin-sqlc.md) and [systemrollout](systemrollout-sqlc.md). The last service's real budget defect was characterized and corrected before movement; the builtin instantaneous lock-probe failure was a test expectation correction for asynchronous connection cleanup, not a product defect claim.

`tools/sql-governance` discovers SQL-looking string literals and execution selectors in production `internal/`, `cmd/` and `pkg/` Go and canonical `.go.tmpl` extension sources. It also discovers method values, so assigning `db.Exec` to a callback cannot hide that execution boundary. Comments and Go test-only files are excluded. Directory names such as `testdata` or a nested `sqlc` are not exemptions; only the exact canonical `internal/db/sqlc` output namespace is handled through its closed source-derived ownership check. Generated filename suffixes are not exemptions. The canonical sqlc output directory has a closed source-derived filename inventory; a forged generated header in an extra file fails. Normal sqlc and extension freshness checks still verify generated content. Test schema/cleanup statements belong to isolated owned fixtures; migrator schema/version and explicit low-level runtime operations remain classified independently from selected domain SQL.

The source-bound registry is [runtime-sql.json](../../../data-governance/runtime-sql.json). At this freeze it contains 884 exact syntax candidates and 173 module owners, including 294 retained fixed/extension/dynamic/advisory/low-level SQL candidates and 590 existing non-SQL selector/string/field candidates. Selector names alone cannot resolve Go types: URL query access, Kubernetes exec, runtime preparation and queue fields are explicitly classified, not silently discarded. Each entry binds the call/literal hash and its enclosing receiver-qualified declaration hash. Every owner additionally binds the whole module source. This catches a changed local query builder behind an unchanged `db.Exec(ctx, query)` call, constant/helper changes, shadowed/receiver scopes, new arguments, moved statements and new sites. Removed entries also require review. The retained SQL allowance may decrease but cannot grow beyond 294. No automatic policy refresh command is shipped.

New unresolved dynamic DELETE construction is forbidden; no such builder is approved. This is bounded syntax and exact-source governance, not a type-resolved whole-callgraph proof. Reflection, arbitrary custom SQL evaluators or adversarially hidden wire protocols are not claimed covered. Canonical generated content, runtime behavior tests and ownership review remain necessary alongside it.
