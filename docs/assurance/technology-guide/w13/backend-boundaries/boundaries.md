## The completed extraction boundary

`internal/userpreferences` receives `Reader`, `RunTx`, `MutationTx` and `ReceiptQueries`, plus an explicit actor, `Command`, optional `Replay` and `audit.Intent`. The service owns optional-array normalization, stored-row validation, serialization, body digest, receipt reservation/replay validation, preference replacement, mandatory audit and receipt attachment. One injected transaction-bound sqlc object performs those writes; no ORM, new SQL, migration, pool acquisition or second persistence abstraction is introduced.

`AuthHandler` retains authenticated-user resolution, the strict 16KiB request reader, one-header key syntax and actor/method/route scope, request-shaped audit metadata, safe error/HTTP mapping and response envelope. The legacy composition setter creates one domain service; aliases to domain interfaces preserve existing caller signatures and provide no second forwarding implementation. Missing read/write capability retains safe 503 behavior. Domain code imports neither HTTP, request context, handler nor server.

Preparation before the extraction established actual PostgreSQL missing/null favorites `23514`/500 and changed-body repeated key/request-ID audit disagreement. The bounded integrity correction restored safe required-array validation and added explicit locked same-body replay/different-body 409 behavior without altering public v1 struct layout. Before/after PostgreSQL 17 and 18/race proofs and post-child backend counts are in the [integrity packet](../preferences-integrity/README.md). The first service run passed 12 handler cases then failed domain test compilation because a boolean shadowed its Replay input; production was not diagnosed as failing. The [service packet](../preferences-service/README.md) retains that original failure and the fixture-only correction. Corrected source `427bcf14` passed 12 handler, 31 domain and 16 real PostgreSQL named cases on each major, with race enabled on PostgreSQL 18, plus vet. Both separate post-child observations returned owned-database counts 0/0/0. These are scoped domain/HTTP/database qualification results, not a whole-backend or whole-program acceptance claim.

## Composition, configuration and contracts

`productionComposition` in `server/app_composition_types.go` is the typed handoff between infrastructure construction, router composition and background startup. `app_runtime_foundation.go`, `app_persistence.go`, `app_kubernetes.go`, `app_identity_cluster.go`, `app_integrations.go`, `app_delivery.go` and `app_runtime_charlie.go` form the composition root. `server/mutation_tx.go:sqlcMutationTxRunner` creates one pgx transaction, binds sqlc queries to that physical transaction, rolls back on callback failure, and commits before returning. The preference service does not introduce another environment read or cache/connection global.

The current setter-heavy composition is a deliberate retained v1 seam. Existing code conditionally enables encrypted/TOTP/SSO features and maps unavailable features to their existing statuses. A future constructor tightening must distinguish required versus optional capabilities; blindly making every nil dependency fatal would alter deployed behavior. No such tightening is made here.

Static SQL belongs in W08 canonical queries/generated methods and durable owned JSON readers/writers in W09's exact inventory. Preference SQL remains unchanged. The new receipt is a versioned owned internal object with bounded writer and strict reader; the documented handler JSON sites relocate to domain owners, leaving unrelated policy entries unchanged. The preference dependency rule forbids the preference domain importing HTTP, handler, server or request context. The extraction lowers only the measured auth named-function ceiling 805→804; unrelated Grafana/tunnel ceilings are preserved. Broader complexity and source-security work remains independent.
