# New supplier snapshot capture and shared payload inspection

This source slice is unqualified. No Go build, test, vet, supplier layer transfer,
publication or runtime job has executed for it. The implementation follows the
[producer trust ordering](update-producer-ordering.md); it closes the source
prerequisite for a new upstream subject that has no Astronomer signature yet.

`NewSupplierDatabaseInspector` owns the reviewed repository, main/Java role,
scanner compatibility, finite timing, destination policy and guarded client.
It clones the network policy and HTTP client value. The underlying transport
remains operator-owned and must be the canonical guarded implementation. Runtime
feeds, catalogs and supplier content cannot choose this constructor authority.
Main and Java select only their fixed schema discovery tags, 2 and 1. Repository
references containing a tag or digest are refused at construction.

`Capture` validates the owned network destination and resolves the discovery tag
once. The resolver captures its immutable manifest digest, fetches only original
manifest and configuration bytes by their exact identities, and validates the
closed single-layer manifest with the existing bounded OCI parser. This is
reviewed transport/content authentication, with no claim of an upstream signature.
The canonical signed consumer still verifies its vendor signature before reaching
that shared parser. This adapter cannot create an authenticated consumer update.

The opaque capture belongs to its particular constructor. `Inspect` rejects a
capture from a different constructor and pins an operator-owned regular file.
Both signed consumer and supplier producer now use one no-write two-pass core:
hash all compressed bytes before reading any archive metadata, then rewind the
same descriptor and enforce exact main/Java members, size and expansion bounds,
closed metadata keys, a second whole hash and inode/size/mtime stability. The
supplier adapter derives metadata size, digest, schema and UTC upstream clocks
from those verified bytes. The signed consumer additionally compares those
derived values with its previously authenticated feed claims. Unknown producer
metadata size is private core input; its 64-KiB ceiling remains unchanged.

An opaque verified supplier payload proves the whole layer and actual metadata
at inspection time under owned timing. It has no published subject or publisher
signature, and it establishes no durable acceptance or actual scan-used database.
All later signing/publication must recheck current candidate/base/catalog
revocation state and payload identity, endorse the unchanged child, and only then
serialize and sign the closed feed. Paths can change after return; later consumers
must verify again. Existing two-GiB compressed, eight-GiB expanded and fifteen-minute
inspection limits remain finite. No extract or output write occurs here.

Source fixtures cover unsigned new main/Java capture without a fabricated feed,
exact immutable resolution and original-byte copies, caller policy/client mutation,
changed discovery tag after capture, no layer or signature request, unapproved
origin rejection before transport, zero/foreign opaque proof, changed/missing
files, canonical cancellation, incompatible/stale/non-UTC/ambiguous metadata and
DownloadedAt failing to refresh stale upstream content. Resolver fixtures bind
invalid manifest/config cases to their actual content hashes rather than failing
only through an unrelated signature mismatch. These fixtures have not run yet.

Complete bounded network layer transfer into owned storage, child endorsement,
feed serialization/publication/readback, durable monotonic transitions, actual
job/report provenance, current supplier payload cadence, fresh-cache/no-egress
and production OIDC execution remain separate work. The whole W04 package is in
progress and this source slice does not approve a release or future tag.
