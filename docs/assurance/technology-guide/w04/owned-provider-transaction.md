# W04 owned provider transaction source draft

This applied source slice was reviewed as an external draft against durable commit `9ee9961e3f8a98ad3ee187b24fe667c90cbb9566`. Formatting is the only Go tool action taken for these provider changes. No compiler, database, SQLC, cluster, or scanner operation has executed for this draft.

The shared canonical provider finalizer returns its actual database receipt as an internal result. The ordinary public provider keeps its existing response, metrics, validation, credential hydration, ETag, retry, and not-modified behavior. No v1 SDK fields or protocol JSON fields are added. An optional private coordinator acquires the existing cluster builtin session lock before opening a serializable transaction, binds that same canonical provider to `queries.WithTx`, and passes the actual finalized receipt to a constructor-owned projection participant within that same transaction. Both initial and precommit physical-authority revalidation are mandatory. Session cleanup uses a fresh five-second context after cancellation; uncertain rollback or unlock state closes the exact hijacked connection rather than returning an owned lock to the pool. Local cleanup does not prove PostgreSQL backend drain; actual database tests must observe that separately. Serializable/deadlock retries are finite and do not retry canceled callers.

The private projection participant is an interface boundary, not an implemented database acceptance repository. No production provider is configured to use this lane yet. The remaining concrete implementation must register the exact opaque verified base and physical TLS/signing authority, promote monotonic epochs and permanent revocation, lock actual source credentials/ready version/current target, enforce current feed/scanner/profile/freshness authority, and refresh accepted-update projection plus rescan outbox using the returned canonical receipt in the same transaction. Ordinary hub providers must be wrapped consistently once this feature is configured; an unwrapped alternate provider could bypass the session lock. Those requirements remain open until the reviewed079 queries are generated and consumed under their separate generator/database lease.

The source tests exercise actual-finalizer-row preservation (including not-modified), private constructor capture, and sanitized cancellation/retry behavior. The tests are unexecuted, and constructor fixtures do not pretend to establish transaction atomicity. Real PostgreSQL17 and18 tests must establish blocked session-lock cancellation, context cancellation during a query, rollback retaining prior projection and positive reports, concurrent current-base/epoch/source/target changes, same-feed receipt refresh without fabricated generation or unnecessary rescan, revocation with no resurrection, and exact session unlock/backend drain. Actual selected scanner/cache/job/report witnesses, runtime freshness UI/API, automatic six-hour report refresh, and supplier whole payload/freshness qualification remain separate unfinished requirements.
