# Physical trust constructor — source only

The root-reviewed source is applied in the isolated durable worktree but has not been compiled or tested. It follows the optional verified-base foundation. The sole compiler lease and actual selected-toolchain gates remain prerequisites; test source asserts intended behavior, not observed outcomes.

DatabaseAuthority captures mounted policy and exact key/root bytes before its private canonical catalog Loader.Load. It never wraps a previously cached loader. Physical fingerprints are versioned and length-framed across policy plus actual material; output strings cannot create opaque proof. The owned LoadUpdate method also uses the same frozen directory, binding, policy and guarded client for canonical signed feed/child loading; its retrieval repository/digest cannot expand trust or timing and both database roles remain required. Base loading and durable Revalidate compare BOTH the current operator mount and the frozen owned snapshot, detecting a rotated mount even when the catalog is cached. The durable repository must revalidate before authority reads and before commit/use; current base/policy/material/epoch and permanent database revocation must also match. Snapshot alone proves historical constructor provenance, not current authorization or scan-used inputs.

Mounted public-key validation is factored from the existing QA public-key helper, preserving that helper's bounds and parser. Trusted roots use the existing canonical Sigstore parser. The canonical trust reader adds no-follow/nonblocking open, regular-file fstat and pre/open/final inode/size/mtime checks. On Unix a controlled FIFO/symlink/stat replacement fixture exercises the precise pre-open phase. Non-Unix preserves the ordinary verifier opener and rejects only this optional strict physical-authority constructor; no new v1 CLI platform restriction is introduced. Current release workflow explicitly ships linux/amd64 and linux/arm64 images, which does not by itself prove a restriction on historical ordinary CLI platform support. File reads are bounded at 1MiB (keys retain the existing 256KiB limit), no DNS/TUF/Fulcio/Rekor request is introduced.

A same-UID privileged local writer can change a file after a check. Canonical verification independently pins each bounded regular descriptor; this snapshot does not claim a local filesystem sandbox or transactional control over mounted rotation. Changed mounts require explicit promotion/revocation and a new owned constructor, never automatic material adoption. Owned-directory cleanup preserves a replaced path.

The QA catalog fixture proves keyed constructor/catalog composition only. The separate virtual Sigstore fixture exercises real offline OIDC certificate/tlog crypto under a local virtual identity/root, not protected GitHub publisher identity or production OIDC candidate startup. No scan job, witness, release publication or supplier payload qualification is inferred.
